# iOS 本地计价缓存与规格倍率优化

> 状态：✅ 代码完成、自动化测试及 Device Hub 基础交互通过，`1.2.3 (260729.16.4)` 已上传 App Store Connect

## 1. 目标

产品智造和风格模板的点数预估改为基于完整规则快照在 iOS 本地即时计算。切换方向、比例、清晰度、动态属性、模型或宣传标识折扣时不再逐项请求报价接口；服务端在最终提交时保持最终计价权。

本轮不修改数据库结构，也不改变现有扣费与任务创建事务。

## 2. 价格规则与缓存

- `GET /api/ais/billing/pricing-snapshot` 返回当前用户生效的图片与模板基础点数、输出规格倍率、动态属性倍率、模型倍率、国家倍率、会员折扣和宣传标识折扣。
- 输出规格优先读取后台 `ais_model_output_spec` 的启用配置，覆盖 1024、1536、2K、4K、8K 等后台已发布规格。
- `Version` 根据实际规则内容生成稳定 SHA-256 指纹；时间戳和签名令牌不参与指纹。
- iOS 使用 `user:<用户 ID>|pricing-rules-image` 作为持久缓存键，并允许读取过期缓存，不再按十分钟周期强制刷新。
- 无缓存时首次联网获取；账号变化、充值成功和会员等级或折扣变化时强制刷新。
- 强制刷新失败时保留上一份有效规则，退出登录时随用户作用域缓存一起清理。

### 2.1 加载可靠性补充

- 产品智造与模板创作将价格规则作为独立 SwiftUI task 并发加载，不再等待页面配置、图片理解预估或模板详情依次完成。
- 缓存缺失时遇到超时、HTTP 408/429、HTTP 5xx、无效响应或缺少数据，会自动尝试最多 3 次；两次重试分别等待 300ms 和 900ms。
- HTTP 401、业务拒绝、任务取消等不可通过短暂等待恢复的错误不会重复请求。
- 自动重试全部失败后，生成按钮改为“重新加载计费规则”，允许用户主动恢复；没有有效规则前仍禁止提交任务。
- 强制刷新失败时不会清除已有缓存，弱网用户继续使用最后一份有效规则进行本地估算。

## 3. 本地计算

`AISLocalPricingCalculator` 统一执行以下顺序：

1. 基础点数；
2. 方向、比例和清晰度倍率；
3. 动态属性倍率；
4. 模型与国家倍率；
5. 向上取整；
6. 会员折扣；
7. 宣传标识折扣。

模板创作使用模板自身基础点数；模板默认清晰度按 `×1` 计算，切换到其他规格后使用对应倍率。字典键按大小写不敏感方式匹配，避免后台键名大小写差异造成错误回退。

本地没有有效规则且无法联网时，页面显示“暂无法估算点数”并禁用提交；已有缓存时可在弱网或离线状态继续切换规格并查看预估。

## 4. 最终校验与兼容

- 新版产品任务和模板生成请求携带 `PricingRulesVersion` 与 `LocalCalculatedPoints`。
- 服务端根据当前规则重新计算，同时比较规则版本和客户端点数。
- 不一致时返回 `PRICE_CHANGED`，包含旧预估、最新点数、原价、优惠金额及最新完整规则。
- iOS 写入最新规则并根据当前选项重新计算，展示“价格规则已更新：原预计 N 点，最新预计 M 点”；当前提交终止，用户必须再次确认。
- 第二次提交仍由服务端重新计算，连续变化、网络失败或规则载荷无效时继续阻止任务创建。
- 未携带 `PricingRulesVersion` 的旧版 iOS 继续使用十分钟快照令牌校验，兼容行为保持不变。

## 5. 界面

- 产品智造与模板创作的比例、清晰度规格仅在非基准倍率时显示中性色 `点数 ×N` 标签，基准 `×1` 不显示。
- `Pro 可用`、`企业可用`等权益要求继续使用独立橙色标签，锁定规格同时展示倍率和权益。
- 模型选择器继续展示同一格式的模型倍率。
- 生成按钮使用“确认生成”与“预计 N 点”两行结构；提交中显示“正在提交”，无规则时显示“暂无法估算点数”。
- 禁用按钮提高文字与背景对比度，并通过 VoiceOver 合并朗读操作与预计点数。

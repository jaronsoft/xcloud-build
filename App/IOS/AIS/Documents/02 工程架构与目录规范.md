# 工程架构与目录规范

## 1. 技术基线

- Swift 6 兼容模式、SwiftUI、Swift Concurrency。
- 最低 iOS 17。
- 使用 StoreKit 2、AuthenticationServices、UserNotifications、PhotosUI 和 UniformTypeIdentifiers。
- 提交 App Store 时使用 Apple 当期要求的正式版 Xcode；按 `2026-04-28` 起生效的要求，上传需要 Xcode 26 或更高版本及 iOS 26 SDK。
- 首版优先使用 Apple 原生框架，避免为基础能力引入大型第三方 SDK。

官方依据：[App Store 提交要求](https://developer.apple.com/app-store/submitting/)、[Upcoming Requirements](https://developer.apple.com/news/upcoming-requirements/?id=02032026a)。

## 3. Target、Scheme 与配置

首版使用一个 App target，至少提供：

| Scheme | 用途 | API | StoreKit/APNs |
| --- | --- | --- | --- |
| `AIS-Development` | 本地开发与模拟器 | 本地或测试环境 | StoreKit Configuration、APNs sandbox |
| `AIS-Overseas` | 海外 TestFlight/生产 | 海外 API | App Store sandbox/production、海外 APNs |
| `AIS-China` | 中国区测试与正式发行 | 中国独立 API | 中国区商品与 APNs |

约束：

- `Bundle ID` 主标识保持 `com.wekarepartners.studio`；调试 target 如需后缀，必须确认不会污染 Sign in with Apple、Associated Domains 和 IAP 测试。
- API URL、区域键、日志级别和功能默认值通过 `.xcconfig` 注入。
- `.xcconfig` 不保存密钥；APNs 私钥、StoreKit 密钥和 Apple 登录 client secret 仅存在服务端安全配置。
- 生产环境不展示环境切换入口。

## 4. 分层与依赖方向

### 4.1 Core

- `Configuration`：环境、区域和构建信息。
- `Networking`：请求构建、统一响应解码、认证刷新、上传下载、重试和错误映射。
- `Persistence`：Keychain、轻量缓存和文件缓存。
- `Routing`：Tab、NavigationStack、Universal Links 和通知深链。
- `DesignSystem`：颜色、字体、间距、卡片、按钮、加载和错误组件。
- `Localization`：字符串目录和服务端错误的本地化兜底。

### 4.2 Features

每个 Feature 可包含：

```text
Feature/
├── Models/
├── Services/
├── ViewModels/
├── Views/
└── Components/
```

依赖只能由 Feature 指向 Core 和显式协议。Feature 之间通过路由或协议协作，不直接访问对方内部 ViewModel。

### 4.3 状态管理

- App 全局只保留会话、环境、路由和轻量能力快照。
- 页面状态由 `@Observable` 或 `ObservableObject` ViewModel 管理。
- 网络服务使用协议注入，便于测试。
- 任务状态以服务端为准；本地只缓存可恢复的任务 ID 和最近快照。
- 余额、交易和报价不得仅依赖客户端乐观状态。

## 5. 网络层

统一 `APIClient` 应具备：

- `MessageModel<T>` 解码；
- JWT 注入与单飞 refresh；
- `401/403` 的会话处理；
- `Accept-Language`；
- `X-Client-Platform: ios`、App 版本和区域标识；
- 超时、取消、指数退避和幂等重试边界；
- multipart 上传、文件下载和进度；
- 大整数 ID 的字符串模型；
- 后端错误码到可本地化错误的映射。

安全重试规则：

- GET 可在网络错误后有限重试。
- 创建任务、确认报价和支付验单只在携带幂等键且服务端支持时重试。
- 上传失败可以按服务端 upload session 恢复；没有恢复协议时重新上传，不猜测成功。

## 6. 实时任务与通知

- 前台优先使用现有 SignalR 状态推送，断线后回退轮询。
- App 进入后台不维持无限网络任务，生成继续在服务端执行。
- APNs 只用于完成、失败和需要用户处理的安全摘要。
- 通知点击通过 `projectId`、`jobId` 或 `runId` 深链进入对应页面。
- 收到通知后仍调用服务端查询真实状态，通知 payload 不作为账务或成果事实来源。
- 设备 token 按用户、环境、区域和设备记录；退出登录时解除用户绑定。

Apple 依据：[Sending notification requests to APNs](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns)。

## 7. 文件、图片和缓存

- 相册选取优先 `PhotosPicker`，只有保存到相册或确需全库访问时申请对应权限。
- 相机只在用户主动拍摄时申请。
- Files 使用系统文件选择器和安全作用域 URL。
- 上传前校验类型、大小、像素和数量；项目核心产品图最多 3 张。
- 私有资产通过带 JWT 的 API 获取，不把临时签名 URL 长期持久化。
- 磁盘缓存设置上限和清理策略；账号删除或退出后清理与账号绑定的本地内容。

## 8. 本地化与可访问性

- 面向用户的文案进入 String Catalog，不在 View 中硬编码。
- 服务端枚举使用稳定 key，名称和说明由响应本地化或客户端资源映射。
- 金额只展示 StoreKit `Product.displayPrice`，不自行拼接货币符号。
- 支持 Dynamic Type、VoiceOver、深色模式、Reduce Motion、键盘避让和横竖屏。
- iPad 使用自适应布局，不把放大的 iPhone 页面当作完成状态。

## 9. 依赖引入门禁

新增第三方 SDK 前记录：

- 解决的具体问题和系统框架不能满足的原因；
- 许可证、维护状态、二进制体积和最低系统版本；
- 收集的数据、联网域名、`PrivacyInfo.xcprivacy` 和 required-reason API；
- 是否支持禁用、替换和移除；
- 中国区是否可用和是否产生跨境数据。

未经审查不得接入广告、指纹识别、跨 App 跟踪或不透明分析 SDK。

## 10. 测试结构

- `AISTests`：API 解码、认证刷新、区域能力、StoreKit 协调、报价状态机和 ViewModel。
- `AISUITests`：登录、模板生成、项目 Agent、购买、任务恢复、隐私和账号删除。
- 使用协议替身模拟后端；支付集成使用 StoreKit Test、Sandbox 和 TestFlight，不能只依赖 mock。

# iOS 任务列表轮询与服务端缓存优化

## 1. 目标

- 非任务页面不再周期性读取整张任务列表。
- 保持活动任务约 5 秒内刷新，不牺牲任务状态实时性。
- Redis 命中请求 P95 低于 200ms，数据库冷回源 P95 低于 1 秒。
- 减少任务列表统计、宽字段读取和媒体地址解析造成的数据库往返与 Redis 占用。
- 保持 AIS Web/H5 分页总数及其他既有调用方兼容。

## 2. 客户端实现

- iOS 只在进入任务页、下拉刷新和提交任务后读取摘要列表，非任务页面不再周期性读取整张列表。
- 任务提交通知携带任务 ID；iOS 每 5 秒调用单任务轻量状态接口，任务进入终态后只刷新一次摘要列表。
- 任务页仅对当前活动任务按 ID 刷新状态，打开任务详情时再读取完整任务。
- 删除任务、下拉刷新等用户主动操作继续使用强制刷新。
- iOS 请求显式传递 `summaryOnly=true&includeTotal=false`，因为任务页只展示首屏列表，不依赖完整总数。
- AIS Web/H5 请求显式传递 `summaryOnly=true&includeTotal=true`；继续编辑、应用方案、复盘等操作按 ID 懒加载详情，并对同一任务的并发详情请求去重。

## 3. 服务端实现

- `GET /api/ais/jobs` 新增可选参数 `summaryOnly`，默认值为 `false`，完整模式保持兼容。
- 摘要 SQL 不读取 `InputJson`、`ClientSnapshotJson` 和 `OutputJson`，只返回列表展示字段。
- 摘要分页使用 Redis 增量缓存，键按用户或访客身份哈希、区域和筛选条件隔离；同一筛选条件的不同页共享连续摘要窗口，登录用户 TTL 为 10 分钟，访客 TTL 为 1 分钟。
- 缓存窗口记录最大、最小任务 ID 和已处理变更版本。刷新时只查询最大 ID 之后的新任务，继续翻页时只按最小 ID 补充当前页需要的更早任务，再按雪花 ID 去重、倒序拼接。
- 新建、排队、终态、删除和改图折叠会把对应任务 ID 写入 Redis 变更日志，各筛选缓存独立消费变更并定向更新；区域变化才要求对应缓存窗口重建。
- 活动任务使用现有 `AIS:JobStatus:{jobId}` 快照批量覆盖状态、进度、结果资产和错误，不因普通进度变化清空分页缓存。
- 同一摘要集合回源时使用 3 秒 Redis 锁；未获锁或 Redis 不可用时自行轻量回源，并由后续高水位查询修复并发覆盖。
- Redis 故障、超时或反序列化失败时立即回退数据库查询，不影响接口可用性。
- 登录用户可以分页读取全部未删除历史任务，不再限制最近 7 天；匿名访客仍遵循访客数据保留时限。
- 旧版 iOS 的 `media`、30 条且未显式传递 `includeTotal`、`summaryOnly` 的请求自动切换摘要模式，只读取 12 条并跳过 `COUNT`。
- `includeTotal=false` 时跳过统计查询，并让 `dataCount` 返回当前页条数。
- 媒体同步先批量读取缓存，只对未命中的资产执行数据库查询；图片、视频和视频首帧共用解析结果。
- 超过 800ms 记录预警，超过 1 秒记录慢请求；日志拆分记录摘要缓存、状态覆盖、隐藏父任务、统计、分页、媒体解析和缓存写入耗时。

## 4. 兼容性与缓存边界

- Redis 只保存任务卡片所需摘要，不保存 `InputJson`、`ClientSnapshotJson`、`OutputJson`；任务详情、继续编辑和复盘仍按 ID 读取详情接口。
- `includeTotal` 默认开启、`summaryOnly` 默认关闭，未升级调用方保持原行为；管理端接口不受影响。
- iOS 关闭完整计数只影响 `dataCount` 语义，不修改任务字段、排序和状态。
- 任务状态快照明确不写入完整 `OutputJson`。
- 区域设置修改后立即递增用户任务列表 revision。

## 6. 上线观察

- 非任务页面不应周期性产生任务列表请求；活动任务仍应在约 5 秒内通过状态接口更新。
- Redis 命中请求 P95 目标低于 200ms，数据库冷回源 P95 目标低于 1 秒。
- Redis 中不应存在完整任务 JSON，也不应出现跨用户、访客、区域或筛选条件复用；新增少量任务时不应重新读取整页。
- 冷请求仍慢时，根据新增分段日志检查生产索引、数据库网络和连接池；历史任务只应在用户继续翻页时按低水位分批回填。

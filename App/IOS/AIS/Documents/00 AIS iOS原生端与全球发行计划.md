## 一、已确认决策

### 1.1 应用标识

- iOS 主应用 Bundle ID 使用中性标识 `com.wekarepartners.studio`，避免把不可变标识绑定到早期产品名称 `AIS`。
- PixaRivo 已作为独立 iPhone App 使用 `com.wekarepartners.pixarivo` 发布，两个 App 可以共用 AIS 账号和服务端账务能力，但不得共用 Product ID、订阅组、App Store Connect 资料或版本时间线；PixaRivo 状态见 [PixaRivo 文档中心](../../PixaRivo/Documents/README.md)。
- App Group 预留为 `group.com.wekarepartners.studio`，只有在引入 Share Extension、Widget 或共享文件容器时启用。
- StoreKit 消耗型积分 Product ID 统一使用 `com.wekarepartners.studio.points.<区域键>.<档位键>`，例如 `cn`、`global`；自动续费订阅使用 `com.wekarepartners.studio.subscription.<套餐键>.monthly`。两类标识均只使用稳定英文键，不写入金额、币种或积分数量。
- URL Scheme 使用 `wekare-studio`，Universal Links 继续使用现有 `https://ais.jaronsoft.com`；产品正式改名后可增加新域名并保留旧链接兼容。
- Associated Domains 预留 `applinks:ais.jaronsoft.com`；需要共享网页登录凭据时再增加 `webcredentials:ais.jaronsoft.com`。
- App 显示名称不由 Bundle ID 决定。App Store Connect 当前使用“`AIS Visual Studio by WeKare`”，客户端开发阶段仍显示“`AIS`”；正式发布前继续完成商标与长期品牌评估。
- 新名称需要覆盖“视觉创作、模板、Agent 与 Skill”整体能力，不再只表达工业产品出图；正式确认后同步更新 `AIS/AGENTS.md`、中英文文案、协议、备案和商店资料。

选择 `com.wekarepartners.studio` 的原因是它与美国 App Store 发行主体和 `wekarepartners.com` 域名一致，同时不会因产品从“产品智造”扩展到模板、Agent、Skill 或后续更名而失效。`jaronsoft.com` 继续作为当前产品官网、分享页、Universal Links 和服务域名，不要求与 Bundle ID 使用同一反向域名。

### 1.2 产品定位

当前产品已经超出早期“`AIS 产品智造`”的工业产品出图定位，原生端应按以下四层能力组织：

- **快速创作**：直接进行图片生成、图片编辑、视频生成、规格选择和成果下载。
- **模板创作**：浏览风格模板，上传自己的图片和资料，一键生成同款并持续修改。
- **Agent 创作**：通过项目对话理解需求、确认上下文、选择 Skill、生成计划、报价并执行多成果任务。
- **Skill 生态**：把可复用的专业创作方法包装为应用，逐步支持官方 Skill、审核后的创作者 Skill 和真实案例。

核心用户可以来自工业制造、外贸、电商、品牌营销、社交内容和普通视觉创作场景。工业产品仍是重要垂直优势，但不再作为产品名称和客户端信息架构的唯一边界。

### 1.3 产品边界

- 首版采用 SwiftUI 原生实现，不使用 WebView 包装现有 AIS 网站作为主体功能。
- 保留聊天式交互，但定位为“创作助手”或“项目对话”，只服务于图片、视频、Skill、项目和成果迭代。
- 风格模板作为首版核心入口，不再被视为工业产品生成的附属功能。
- Agent 只能执行服务端发布的声明式 Skill，继续使用“生成计划 → 展示报价 → 用户确认 → 幂等启动”协议。
- 首版不提供开放式通用聊天、任意联网搜索、用户自定义代码或工具、用户间私聊和匿名聊天。
- 首版不开放用户自由发布社区内容、评论、关注、创作者提现和 Skill 市场交易；公开案例仅展示后台审核通过的精选内容。
- 当前 StoreKit 消耗型积分商品仍是首个支付闭环；自动续费订阅作为下一阶段独立实施，采用四档月付、地区独立额度、共用会员等级和当期订阅点数，不与 H5 充值套餐混为同一体系。
- App 内积分和付费数字能力统一使用 StoreKit In-App Purchase，不接入 Apple Pay。Apple Pay 仅适用于未来可能出现的实体商品或 App 外消费服务，不属于当前范围。
- 当前不向 Skill 创作者提供现金收益和提现。创作者可以提交经审核的 Skill，但平台定价不产生面向创作者的可提现余额。

### 1.4 发行与运营主体

- `WeKare Partners LLC` 持有 Apple Developer Organization 账号，负责 App Store Connect、签名证书、IAP 商品、海外发行和 Apple 结算。
- `扬州市佳融信息技术有限公司` 作为中国大陆实际运营主体，负责 APP/ICP 备案、生成式 AI 应用登记、中国区用户协议、个人信息保护、内容安全、投诉举报和监管联络。
- 美国公司与佳融公司需签署中国大陆软件及品牌授权、运营合作、数据处理、安全责任和 IAP 收入结算协议。
- 中国大陆不是简单借用佳融备案号；佳融必须实际承担中国区服务提供者和运营责任。

## 二、原生端技术方案

### 2.1 工程与平台

- 在仓库 `App/IOS/AIS/` 新增独立原生工程，与 `AIS/` Web 前端分离，共用现有 AIS WebAPI，不复制后端业务规则。
- 使用 Swift、SwiftUI、Swift Concurrency 和 StoreKit 2，最低支持 iOS 17。
- 提交 App Store 时使用 Apple 当期要求的正式版 Xcode 和 iOS SDK。
- 网络层统一封装 JWT、刷新登录态、区域 API 地址、超时、重试、错误本地化和大整数 ID 字符串解析。
- 登录凭证保存到 Keychain；普通界面状态和非敏感偏好使用 `UserDefaults`，不得保存供应商密钥或支付凭据。
- 图片、视频和文件使用原生 Photos、Camera、Files、Share Sheet 和系统下载能力。
- 长任务由现有 SignalR/轮询恢复链路提供状态，App 进入后台后依赖服务端任务继续执行，完成后通过 APNs 通知用户。

### 2.2 模块划分

- `AppCore`：环境、依赖注入、路由、日志、错误和中英文资源。
- `Networking`：API Client、JWT、SignalR、上传下载和资产 URL 解析。
- `Account`：邮箱登录、Sign in with Apple、资料、隐私授权和账号删除。
- `CreativeAgent`：项目对话、需求澄清、上下文、记忆建议、计划与报价确认。
- `Templates`：风格模板浏览、搜索、分类、详情、动态字段、素材上传、同款生成和模板作品。
- `Generation`：图片生成、图片编辑、视频生成、任务状态和失败退款说明。
- `Projects`：项目、历史会话、成果看板和单成果继续修改。
- `Assets`：相册、相机、文件导入、素材库、保存和分享。
- `Billing`：余额、StoreKit In-App Purchase 商品、购买恢复、订单记录和退款状态。
- `Gallery`：只读展示后台审核通过的公开案例和真实 Skill 示例。
- `Settings`：语言、模型与备案信息、隐私政策、用户协议、投诉举报、版本和账号删除。

### 2.3 环境与区域

- 开发环境使用本地或测试 API，生产环境不得由用户手动输入任意 API 地址。
- 海外生产环境连接海外 API、数据库、Redis、对象存储和允许的海外模型。
- 中国生产环境连接中国区独立 API、数据库、Redis、对象存储及已备案模型白名单。
- 区域由 App Store storefront、账号所属区域和服务端能力配置共同确定，不依赖 GPS，也不允许客户端自行切换绕过区域限制。
- 中国区与海外区账号可按既定规则同步基础身份，但积分、余额、订单、订阅、提现和原始生成数据不得跨区合并。
- App Review Notes 必须解释区域差异，并提供海外和中国区可审查测试账号；未完成中国区备案前不勾选 China mainland storefront。

## 四、后端与公共接口改造

### 4.1 iOS 能力配置

- 扩展现有 AIS capabilities 响应，增加 iOS 最低版本、区域、可用登录方式、StoreKit 商品键、视频开关、公开内容开关、模型公示信息和协议版本。
- 客户端只根据服务端能力展示功能；模型供应商、价格、区域限制和合规开关继续由后端控制。
- API 的所有 `Id` 继续以字符串传输，iOS 数据模型不得将雪花 ID 解析为可能丢失精度的浮点数。

### 4.2 Apple 登录

- 后端校验 Apple identity token 的签名、issuer、audience、过期时间和 nonce。
- 以 Apple `sub` 作为稳定第三方身份键；用户首次授权后即使 Apple 不再返回姓名和邮箱，也能恢复账号。
- 支持隐藏邮箱，并明确 Apple 账号与现有邮箱账号的绑定、冲突提示和解除规则。

### 4.3 StoreKit 2 与积分

- AIS 积分、Skill 使用权和 App 内生成能力属于数字商品，支付实现固定为 StoreKit In-App Purchase，不使用 Apple Pay。
- 现有后台“分地区充值价格”继续作为积分规则唯一业务配置源，iOS 不另建一套积分比例、首充赠送、促销或优惠档位。
- App Store Connect 是 iOS 实际成交价格和本地化币种的来源；客户端展示 StoreKit 返回的价格，不使用后台金额替代 Apple 成交价格。
- iOS 只支持固定积分包，不提供 Web 端的任意金额输入。后台未绑定有效 StoreKit Product ID 的档位不得显示在 iOS。
- 后台固定档位需要补充稳定档位键、StoreKit Product ID、iOS 启用状态、区域、排序和规则版本；原有 `Amount`、`Points` 继续服务 Web 端及后台核算。
- iOS 先读取后台区域充值配置，再通过 StoreKit 拉取对应商品，只展示两边都存在且处于启用状态的交集；配置不一致时隐藏问题档位并记录管理告警。
- StoreKit 返回的价格只负责展示和扣款，后台返回的基础积分、注册赠送、首充赠送和促销赠送负责权益展示；客户端不得按 Apple 价格自行计算到账积分。
- 客户端提交签名交易信息，后端通过 App Store Server API 验证并以 `originalTransactionId`、`transactionId` 和商品 ID 做幂等处理。
- 接入 App Store Server Notifications V2，处理退款、撤销、争议和测试通知。
- Apple IAP 购买的积分归入永久充值积分，不设置过期时间。
- Web 端已有永久积分可以在 iOS 使用，但 iOS 内不得展示或引导微信、支付宝、Stripe、PayPal和网页购买。
- 购买完成但网络中断时，App 重启后必须重新同步未完成交易；重复通知不得重复到账。

#### 现有后台规则基线

- 中国大陆与美国/默认地区独立定价，不做客户端汇率换算。
- 当前中国大陆基础套餐为 `¥10 = 1000 点`，最低充值 `¥2`，自定义金额基准为每元 `100 点`。
- 当前中国大陆注册赠送 `300 点`，首次充值达到 `¥10` 赠送 `200 点`。
- 当前美国/默认地区基础套餐为 `$4.99 = 1000 点`，最低充值 `$4.99`，自定义金额基准为每美元 `100 点`。
- 当前美国/默认地区注册赠送为 `0 点`，首次充值达到 `$10` 赠送 `200 点`。
- 两个地区均由后台维护多档优惠套餐；各档 `Amount`、`Points`、每货币单位积分和折扣仅作为当前配置读取，不在 iOS 源码或 App Store 文案中硬编码。
- 两个地区当前限时促销均未开启；开启后由后台起止时间和额外赠送比例决定，不要求重新发布 iOS。

#### iOS 商品与后台档位映射

- 后台为每个 iOS 固定档位绑定唯一 StoreKit Product ID，并保存积分规则版本和生效时间。
- 同一 Product ID 在生效期间不得直接改变基础积分；需要调整积分时创建新档位键和新 Product ID，旧商品停止新购但保留历史验单能力。
- 服务端按照 Apple 交易的 storefront、productId、purchaseDate 和用户所属区域匹配后台档位，禁止客户端传入积分数量。
- 下单前接口返回商品键、基础积分、首充赠送、促销赠送、预计总积分和规则版本；后端在验单到账时再次校验并保存最终积分快照。
- 注册赠送继续在账号创建链路发放，不与 StoreKit 交易重复结算。
- 首充状态以全账户首次成功充值为准，必须在服务端原子占用，避免 Web 与 iOS 并发购买重复领取首充赠送。
- 限时促销以 Apple 交易 `purchaseDate` 和对应历史规则版本判断，后台必须保留已生效规则供延迟交易、退款和对账使用。
- Apple 佣金只影响平台结算收入，不从用户已展示的积分中扣减。

### 4.4 自动续费订阅与区域定价

- 自动续费订阅与充值制独立：订阅按周期发放会到期的订阅点数，充值继续发放永久积分。
- 四档月付套餐使用 `starter / creator / pro / max`，分别授予 `VIP / Plus / Pro / Max` 共用会员等级。
- 中国大陆目标月费为 `¥19.9 / ¥49.9 / ¥99.9 / ¥199.9`，美国目标月费为 `$9.99 / $19.99 / $69.99 / $99.99`。
- 中国与美国使用相同等级和核心功能，但月度点数按地区价格、模型成本和毛利分别测算；其他国家逐国人工定价，未审批的 storefront 不开放。
- 首发只提供月付和首个计费月约七折的 introductory offer，不提供免费试用、年付和 Billing Grace Period。
- 有效会员等级从充值、订阅和管理员授权来源中取最高等级；订阅结束后回落到仍有效的其他来源。
- 订阅点数优先于永久积分消耗并在周期结束时清零，永久积分不受订阅取消、到期或换档影响。
- 完整的 Product ID、地区规则、额度测算、促销、账务和验收规范见 [iOS 自动续费订阅与区域定价策略](./21%20iOS自动续费订阅与区域定价策略.md)。

### 4.5 创作者结算边界

- 当前版本不建立创作者现金收益承诺，不提供收益余额、收款资料、提现申请和提现审核入口。
- 创作者 Skill 可以免费使用或由平台统一设置积分价格；用户支付的积分全部按平台数字服务收入和任务成本处理。
- 已存在的 `AISSkillRevenue`、`AISSkillWithdrawal` 及相关后台能力保持 Feature Flag 关闭，不进入 iOS、Web 用户端或正式运营流程。
- 如未来重新引入创作者分成，需要单独完成 Apple 政策、税务、合同、反洗钱、退款冲正和各地区支付合规评审，不沿用当前版本默认开启。

### 4.6 通知、隐私与删除

- 新增设备 Token 注册、更新、注销和多设备管理接口，按用户、区域和环境隔离 APNs Token。
- 通知内容默认不包含提示词、原始图片、商业机密或敏感素材，只显示任务状态和安全摘要。
- 上传个人图片、品牌素材或可能含个人信息的内容前显示用途、第三方 AI 处理和存储说明，并记录同意版本。
- 账号删除覆盖登录身份、AIS 业务数据和无法立即删除数据的法定保留说明，不允许仅提供客服邮箱代替 App 内删除。

## 五、聊天式创作 Agent 边界

### 5.1 允许行为

- 收集产品、品牌、目标市场、渠道、风格、画幅和成果数量。
- 对缺失信息进行有限追问，并把回答转换为结构化 Skill 输入。
- 推荐后台已发布的官方或审核通过 Skill、风格模板和直接创作入口。
- 展示成果计划、预计积分、服务费和预计耗时。
- 由用户一次确认后启动受控任务。
- 对指定成果提出修改建议并发起单成果重新报价。
- 建议保存个人偏好、品牌规范、产品事实和项目规则，只有用户确认后写入记忆。

### 5.2 禁止行为

- 回答与视觉创作、项目上下文和已发布 Skill 无关的无限话题。
- 自主调用未在 Skill 白名单中的模型、工具或外部服务。
- 未经用户确认执行付费任务、连续扣费或扩大成果数量。
- 把内部 Prompt、模型密钥、Skill 私有规则或其他用户数据返回给用户。
- 把项目消息、上传素材和生成结果默认公开。
- 在中国区调用未备案模型或绕过输入、输出内容安全检查。

### 5.3 安全控制

- 服务端同时执行输入和输出内容安全检查，客户端提示不能替代服务端拦截。
- 对违法、色情、暴力、仇恨、侵权、冒充真人和敏感个人信息请求提供明确拒绝与申诉入口。
- 项目消息、引用记忆、报价和实际执行 Skill 版本保留可审计关联。
- 用户可删除项目消息和记忆；因支付、风控或法定义务需要保留的记录应脱敏并说明保留期限。

## 八、测试与验收

### 8.1 自动测试

- 网络层覆盖成功、业务失败、`401/403`、超时、断网、重试和大整数 ID。
- Apple 登录覆盖首次授权、隐藏邮箱、重复登录、nonce 失败和账号冲突。
- StoreKit 覆盖成功、取消、待处理、重复通知、退款、撤销、断网恢复和沙盒环境。
- 充值配置覆盖后台档位缺少 Apple 商品、Apple 商品下架、区域不匹配、规则版本变更和本地化价格变化。
- 首充赠送覆盖 Web/iOS 并发首充，限时促销覆盖交易延迟完成和跨越促销结束时间。
- Agent 覆盖报价过期、重复确认、余额不足、并发确认、部分失败和失败退款。
- 记忆覆盖未确认、停用、删除、跨用户和跨项目隔离。
- 区域能力覆盖海外模型不会出现在中国区、中国支付入口不会出现在 iOS、未完成备案时中国区不可用。

### 8.2 手工验收

- 在不同尺寸 iPhone 和 iPad 上检查中英文、动态字体、横竖屏、键盘和 VoiceOver。
- 使用相机、相册、Files 上传素材，拒绝权限后仍可使用其他导入方式。
- 创建项目并通过对话完成“工业产品上市包”报价、确认、生成、失败恢复和单图修改。
- 选择风格模板，填写动态字段并上传素材，完成同款生成、历史恢复和再次编辑。
- 购买积分后强制退出 App，重新打开时余额和交易状态正确。
- 生成任务在后台完成后收到通知，点击能定位到对应项目和成果。
- 删除账号后旧 Token 失效，重新登录不恢复已删除业务数据。
- 审核测试账号无需额外硬件或人工操作即可覆盖核心功能。

### 8.3 首版完成标准

- 核心流程不依赖 WebView。
- 没有微信、支付宝、Stripe、PayPal 或网页充值引导。
- 没有 Apple Pay、创作者现金收益或提现入口；App 内数字商品仅通过 StoreKit In-App Purchase 购买。
- 所有付费任务都先展示报价并由用户确认。
- App 内可以完成账号删除、隐私查阅、投诉举报和客服联系。
- 海外 TestFlight 核心场景通过，StoreKit 沙盒账务可对账。
- App Review Notes、演示账号、隐私政策、用户协议和后端服务均可用。
- 中国大陆只在备案、登记、区域部署和正式合规验收全部完成后开放。
